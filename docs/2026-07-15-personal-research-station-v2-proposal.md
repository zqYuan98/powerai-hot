# 个人研究站 v2 · 方案初版

**日期**：2026-07-15
**状态**：初版待讨论
**定位声明**：本方案以「**个人 AI 情报研究站**」为主产品重新组织整体架构——先服务个人的 AI 学习与研究，电力业务情报作为第二层独立视图。不受当前实现约束，从初衷出发设计；与现状的取舍映射见 §11。

---

## 一、定位与第一性原则

### 产品是什么

一个**单用户**（我）的 AI 情报学习系统。它和资讯聚合站（AIHOT / ai-news-aggregator）的本质区别：聚合站的终点是"读到"，研究站的终点是"**学到**"——信息进来后要经过筛选、精读、沉淀，最终变成可检索、可关联、能指导工作的个人知识资产。

核心循环：

```
获取(自动) → 筛选(15分钟晨读) → 精读(我挑的少数) → 沉淀(笔记+卡片) → 复用(检索/研报/工作)
```

衡量成功的不是"平台每天入库多少条"，而是：
1. 每天早上 15 分钟，我确信没有漏掉我关心方向上的重要进展；
2. 每周我真正精读并留下笔记的内容 ≥ 3 篇；
3. 三个月后我能凭一次检索找回"当时看过的那篇"，并且它已带着我的笔记。

### 三条继承的原则

1. **代码优于模型**：模型只打维度分/做生成，合成、排序、决策全在代码，配置可调、全库可重算（aihot v10 经验，已验证有效，不动）。
2. **信源分级**：T1 官方一手 / T1.5 官方社媒 / T2 媒体解读，tier 进入评分权重（不动）。
3. **供给密度决定产品形态**：AI 情报日供给数百条 → 热榜/信息流形态成立；电力垂直日供给 10-40 条且无公共热度 → 告警/简报形态。两层不共用一套形态。

### 一条新原则

4. **以"研究主线"为中心，而不是以"频道"为中心**。频道（前沿论文/大模型动态/…）是内容的属性，主线（文档理解与OCR/缺陷检测/…）是**我的学习议程**。研究站的一切组织——评分、晨报、周报、知识库——都围着主线转。这是 v2 与现状最大的结构差异。

## 三、研究主线体系（v2 核心）

### 3.1 主线是一等公民

新表 `threads`，用户可增删改、可暂停、可调权重：

```
threads(id, name, description, keywords[], weight, status[active|paused],
        created_at, updated_at)
```

`description` 是写给评分模型看的一段话（这条主线关心什么、不关心什么），`keywords` 供规则回退与检索。

### 3.2 种子主线（按我的方向，6 条初版）

| # | 主线 | 描述要点 | 权重 |
|---|------|---------|------|
| 1 | 文档理解与 OCR | 版面分析、表格/公式识别、文档解析(MinerU/PaddleOCR/Surya 类)、文档多模态 | 1.0 |
| 2 | 目标检测与缺陷识别 | 检测新范式、小目标、少样本/异常检测、工业质检 | 1.0 |
| 3 | 多模态大模型 | VLM、grounding、视频理解、多模态数据与评测 | 0.9 |
| 4 | 边缘部署与模型压缩 | 量化/蒸馏/剪枝、TensorRT/RKNN/昇腾、端侧推理 | 0.8 |
| 5 | 大模型与 Agent 通识 | 前沿模型发布、Agent 工程、训练/推理基础设施 | 0.6 |
| 6 | AI × 电力场景 | 视觉/OCR/大模型在电网基建/巡检/安监的落地 | 1.0 |

主线 5 权重低是有意的：通识要看，但不该淹没主业方向。主线 6 是研究站与电力雷达之间的桥。

### 3.3 主线的动态演化

- **新增主线**：新条目由模型正常打贴合度；**存量回溯**用 embedding 余弦（主线 description 的向量 × 已存文章向量）给出临时贴合分，纯代码、零模型调用——立刻能看到"如果我早关注这条线，过去一个月有什么"。
- **暂停主线**：不再进晨报分桶，历史归档保留。
- 调权重 → 全库重算学习价值分（沿用现有回测机制）。

| 信源 | 方式 | tier | 说明 |
|---|---|---|---|
| **GitHub Releases 关注清单** | `github.com/{owner}/{repo}/releases.atom`（标准 RSS，零反爬） | T1 | ultralytics、PaddleOCR、mmdetection、vLLM、MinerU、Surya、ComfyUI 等 15-20 个与主线强相关仓库的版本发布——对工程学习价值极高 |

## 五、分析管道改造（评分轴：从"通用五维"到"主线贴合"）

四段式结构、预筛闸门、评分/富化并行 fork、失败互不拖累——全部保留。改的只有 scorer 的输出和合成公式。

### 5.1 scorer 输出（一次调用）

```json
{
  "dims": {"firsthand": 0-100, "utility": 0-100, "depth": 0-100},
  "affinity": {"1": 0-100, "2": 0-100, ..., "6": 0-100},
  "reason": "一句话：为什么值得读 / 归入哪条主线"
}
```

提示词注入 6 条主线的 name+description（约 300 tokens 增量，单次调用不加次数）。原五维中的 `relevance` 被 affinity 矩阵取代，`impact` 并入 depth/reason，减一维。

### 5.2 代码合成：学习价值分

```
primary_thread = argmax_i(affinity_i × thread_weight_i)
thread_score   = max_i(affinity_i × thread_weight_i)

learn_score = (0.50×thread_score + 0.20×utility + 0.15×depth + 0.15×firsthand)
              × tier系数 × kind系数
```

- 权重全在 `scoring_config`，改配置→全库秒级重算（机制照旧）。
- 精选判定：每条**主线**独立阈值（取代每频道阈值）。
- `channel` 字段保留作粗桶兼容，前端导航让位于主线。

### 5.3 成本

与现状同量级：预筛 1 次便宜模型 + scorer/enricher 各 1 次。affinity 只是加长 prompt，不加调用数。

## 六、学习层（研究站的心脏）

### 6.1 今日精选 v2：按主线分桶的晨报

- 零 LLM 装配照旧，**分桶从频道改为主线**：6 条主线各一节 + 「视野」（通识溢出）一节。
- 每节上限 N 条（配置，默认 3），总量控制在 15 分钟读完。
- 每条带：译题/摘要/推荐理由（入库时已生成）+ 一个动作按钮「⭐ 加入精读」。
- 论文条目带 arXiv/PDF/代码链接（现有能力）。

### 6.2 精读队列（新增，学习闭环的缺失环节）

现状的断裂：晨读扫到好东西 → 没有下一步 → 忘了。v2 补上 triage：

```
reading_queue(id, article_id FK, status[queued|reading|done|dropped],
              added_at, started_at, finished_at, note_draft)
```

- 信息流/晨报任何条目 ⭐ → 入队（取代"收藏即生成卡片"）。
- 队列页按主线分组，显示积压天数；周报里提醒积压。
- 状态推进：`queued → reading → done`；`dropped` 也是合法出口（决定不读也是 triage）。

### 6.3 知识卡片 v2：从"收藏副产品"改为"精读毕业证"

现状卡片没人用（favorites=1），根因是**卡片生成在阅读之前**——自动摘要一篇没读过的文章，没有学习含量。v2 反转时序：

- 队列条目标记 `done` 时弹出笔记框（三行即可：这篇解决什么/对我有什么用/要不要跟进）；
- 卡片 = 模型草稿（问题/方法/结论/与电力场景关联——结构沿用）**+ 我的笔记**，笔记字段永远置顶；
- 卡片自动挂到 `primary_thread`，进个人知识库。

### 6.4 个人知识库 v2

- 按主线归档 + 全文检索（SQLite **FTS5**，标题/摘要/笔记/卡片全字段，零新依赖）；
- 卡片间关联：同簇/同标签/embedding 近邻的"相关卡片"（纯代码）；
- Phase 4 升级为问答：RAG over 卡片+摘要（embedding 已有，量级几百条，内存余弦即可）。

### 6.5 主线周报 v2：从"新闻摘要"改为"学习日志"

每周一生成，每条主线一节：

1. **本周该线发生了什么**（精选主条 top-k，LLM 综合——现有 writer 能力）；
2. **我读了什么**（本周 done 的队列条目 + 笔记摘录——纯代码拼装）;
3. **积压提醒**（queued 超过 7 天的条目数）。

周报因此有了两种素材：世界的进展 + 我的消化程度。这是"研究站"和"聚合站"在产物上的分水岭。

### 6.6 主题研报

保留现状（按需触发、库内素材、状态机），无改动。

## 七、电力雷达（第二层，独立视图、独立价值轴）

**明确降级为 Phase 3**，但设计现在定型，避免研究站的实现给它埋障碍。

### 7.1 形态：告警优先，不做热榜

- **商机告警**：新招标命中业务关键词 → 飞书即时推送（webhook 已就绪）+ 雷达页置顶；
- **政策晨报**：每晨一节（可并入今日精选末尾"电力雷达"节）；
- 不做小时级热点、不做热度排序——垂直供给密度撑不起，也不需要。

### 7.2 价值轴：商机分（纯代码，零模型总分）

```
商机分 = 业务匹配度 × 金额量级系数 × 截止紧迫度系数
```

- 业务匹配度：模型对"布控球/视频监控/无人机巡检/AI识别/边缘终端"能力清单打 0-100（一个维度分）；
- 金额/截止日：从公告结构化抽取（模型抽取字段，代码算系数）；
- 阈值告警，全部配置化。

### 7.3 供给（此层的全部难点，按 ROI 排序）

1. **电力公众号**接入自建桥（§4.3 建好后边际成本≈0）——电力行业事实上的官方 RSS；
2. **nea/ndrc 政策列表页**采集器（静态页，1-2 天/个）；
3. **国网 ECP + 重点省政采**招标检索采集（Playwright + 会话，最难也最值钱）；
4. 北极星正文抓取（提升摘要质量，可最后做）。

## 八、运行形态：采集与 Web 解耦

现状断采的根因是采集寄生在 Web 进程里。v2 拆开：

- `jobs/ingest.py` 独立 CLI（复用 `services/ingest.ingest_once`，只是换宿主）：`python -m jobs.ingest --group news`；
- **Windows 任务计划程序**注册三个任务：资讯每小时、论文每日 06:00、晨报 07:00（一条 `schtasks` 脚本进仓库）；
- Web 后端（FastAPI + Next.js）纯读写界面，想开就开；
- 后续若要机器不开也采：同一 CLI 丢到 GitHub Actions（ai-news-aggregator 模式）或小 VPS，架构不变只换宿主。

个人研究站不需要公网部署——**门户/鉴权/TLS 那条生产化路线整体冻结**（代码保留，不再投入）。

## 九、数据模型改动汇总

```
新表
  threads         (id, name, description, keywords[], weight, status, ...)
  reading_queue   (id, article_id FK, status, added_at, started_at,
                   finished_at, note_draft)

articles 改动
  + primary_thread_id FK         # argmax 主线
  + thread_affinity JSON         # {thread_id: 0-100}，回测原料
  ~ dim_scores JSON              # 缩为 {firsthand, utility, depth}
  （channel/kind/meta/embedding/cluster 等全部保留）

knowledge_cards 改动
  + thread_id FK
  + my_note TEXT                 # 用户笔记，与模型生成字段分离

scoring_config 改动
  ~ 频道阈值 → 主线阈值
  + 学习价值分权重组 + 晨报每节上限 + 商机分参数（Phase 3）

全文检索
  FTS5 虚表 articles_fts / cards_fts（SQLite 内建，零依赖）
```

迁移沿用轻量方案（create_all + 缺列 ALTER），存量文章的 affinity 用 embedding 余弦回填。

## 十三、风险与对策

- **主线贴合度提示词冷启动不准**：靠"改权重/阈值→秒级重算"迭代（机制已验证）；affinity 原始分永远落库，公式随便改。
- **精读队列变成第二个收藏夹（只进不出）**：周报积压提醒 + 队列页显示积压天数；`dropped` 无罪化，鼓励清空。
- **自建公众号桥被微信风控**：桥挂了信源健康会亮红（现有机制）；保留第三方桥 URL 作降级配置。
- **ECP/政采反爬**：最难的供给放在 P3 且单列，失败不影响研究站主线；实在不行降级为"每日人工检索链接清单"半自动。
- **单人精力**：P1/P2 都是纯本地改造无外部依赖，两周内研究站可用性即质变；P3 独立成块，可暂停。
